## 1 我对委托的理解

**[客户]** Brief 提出的是一件以“照料如何建立信任”为主题的互动作品：可理解、有生命感、有关系感、可独立演示。

**[方案]** 我的理解是，观众需要同时感受到“它的回应与我的行为有关”和“它并不总是围着我转”。因此产品需要同时满足**可理解的输入、可辨识的需要和一定程度的自主行动**。

本轮最大的设计风险有两个相反的方向：
- 角色看起来很丰富，但观众不知道自己能做什么；
- 操作很清楚，但角色只像响应按钮的动画。

我会用明确工具降低首次学习成本，再通过休息、饱腹和靠近边界保留角色自己的节奏。我**不建议**在第一轮同时交付全部生态、代际与复杂骨骼系统——它们增强世界感，但不能直接证明核心关系体验成立。首轮成功应是：观众能完成一次有效照料、读懂一次自主选择，并理解一次成长变化。

## 2 产品主张与设计假设

**[客户]** 产品主张为“照料如何建立信任”。

**[方案]** 三种照料对应饱腹、乐趣和信任，休息对应精力；成长是持续相处的阶段标记。以下为待验证假设，不是结论：

| 编号 | 假设 | 验证方式 |
|---|---|---|
| H1 | 明确的工具入口比完全依赖自然手势更容易被首次观众理解 | Feed / Play / Pet 三入口，首次可用性测试（A1 10） |
| H2 | 观众通过移动距离、耳尾姿态和声音感知关系，数值面板只起辅助作用 | 先完成状态表达，再细化毛发与光影 |
| H3 | 有原因、可很快恢复的拒绝不会破坏体验，反而增强生命感 | 初次体验测试观察 |
| H4 | 三个环境可帮助读懂成长；不需要完整生命轮回才能形成收尾 | 成年后展示照料回顾；长者、繁衍、基因留作扩展 |

## 4 用户与场景假设

- **[客户]** 主要用户为第一次接触作品的普通观众，单轮一位操作者，其他人可旁观；环境为配备摄像头、鼠标和扬声器的电脑。
- **[方案]** 目标显示范围 1280×720 至 1920×1080。
- **[方案]** 单轮约 3–5 分钟作为原型节奏目标（原 brief 未给出固定时长）；未完成成长也允许主动结束，不以快速通关为评价标准。
- **[方案]** 本轮是可演示原型，**不承诺**无人值守整日运行、多观众同时控制或任意灯光条件。
- **[待确认]** 实际设备、目标显示尺寸、左右手与坐站姿的测试条件由项目负责人确认。

## 5 范围和方案选择

### 5.1 本轮必须完成 [方案]
开始与输入选择；摄像头手部位置与捏合确认；鼠标替代；Feed、Play、Pet；饱腹、乐趣、精力与信任；自主探索与休息；对快速近身动作的躲避；三章成长；状态提示、声音与静音；照料统计和重新开始；源代码、运行说明与演示材料。

Processing Java 本轮交付一个**视觉与运动验证工程**，读取同一参数和匿名状态回放；正式交互原型以浏览器为主。不把两个尚未联通的工程描述成完整装置。

### 5.2 暂缓范围 [方案]
自主捕猎、完整猎物生态、八节脊柱和双骨骼 IK、基因遗传、长者与重生、持续档案、训练新的动作模型、开放对话与云端生成，均不作为本轮验收前提。原型 A 的相关系统作为技术研究材料。

### 5.3 我比较过的三条路线 [方案]

| 路线 | 优点 | 取舍 |
|---|---|---|
| 完全自然手势 + 自主生态（原型 A 方向） | 少界面，观察感强 | 初次参与门槛较高，首轮暂不选 |
| **三个工具 + 需要反馈（原型 B 方向）** | 易理解，便于验证照料因果 | **选为主路线**，用自主休息减少机械感 |
| 直接加入自由对话 | 易表达角色个性 | 增加延迟和内容范围，不能先解决动作理解，暂缓 |

选择第二条路线的代价是观众需要主动切换工具。我的应对是：**让工具表达“准备做什么”，让角色状态决定“现在是否接受”**，而不是把每个按钮都做成必然成功的命令。
