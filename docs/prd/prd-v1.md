## 1 我对委托的理解

**[客户]** Brief 提出的是一件以“照料如何建立信任”为主题的互动作品：可理解、有生命感、有关系感、可独立演示。

**[方案]** 我的理解是，观众需要同时感受到“它的回应与我的行为有关”和“它并不总是围着我转”。因此产品需要同时满足**可理解的输入、可辨识的需要和一定程度的自主行动**。

本轮最大的设计风险有两个相反的方向：
- 角色看起来很丰富，但观众不知道自己能做什么；
- 操作很清楚，但角色只像响应按钮的动画。

我会用明确工具降低首次学习成本，再通过休息、饱腹和靠近边界保留角色自己的节奏。我**不建议**在第一轮同时交付全部生态、代际与复杂骨骼系统——它们增强世界感，但不能直接证明核心关系体验成立。首轮成功应是：观众能完成一次有效照料、读懂一次自主选择，并理解一次成长变化。

## 2 产品主张与设计假设

**[客户]** 产品主张为“照料如何建立信任”。

**[方案]** 三种照料对应饱腹、乐趣和信任，休息对应精力；成长是持续相处的阶段标记。以下为待验证假设，不是结论：

| 编号 | 假设 | 验证方式 |
|---|---|---|
| H1 | 明确的工具入口比完全依赖自然手势更容易被首次观众理解 | Feed / Play / Pet 三入口，首次可用性测试（A1 10） |
| H2 | 观众通过移动距离、耳尾姿态和声音感知关系，数值面板只起辅助作用 | 先完成状态表达，再细化毛发与光影 |
| H3 | 有原因、可很快恢复的拒绝不会破坏体验，反而增强生命感 | 初次体验测试观察 |
| H4 | 三个环境可帮助读懂成长；不需要完整生命轮回才能形成收尾 | 成年后展示照料回顾；长者、繁衍、基因留作扩展 |

## 4 用户与场景假设

- **[客户]** 主要用户为第一次接触作品的普通观众，单轮一位操作者，其他人可旁观；环境为配备摄像头、鼠标和扬声器的电脑。
- **[方案]** 目标显示范围 1280×720 至 1920×1080。
- **[方案]** 单轮约 3–5 分钟作为原型节奏目标（原 brief 未给出固定时长）；未完成成长也允许主动结束，不以快速通关为评价标准。
- **[方案]** 本轮是可演示原型，**不承诺**无人值守整日运行、多观众同时控制或任意灯光条件。
- **[待确认]** 实际设备、目标显示尺寸、左右手与坐站姿的测试条件由项目负责人确认。

## 5 范围和方案选择

### 5.1 本轮必须完成 [方案]
开始与输入选择；摄像头手部位置与捏合确认；鼠标替代；Feed、Play、Pet；饱腹、乐趣、精力与信任；自主探索与休息；对快速近身动作的躲避；三章成长；状态提示、声音与静音；照料统计和重新开始；源代码、运行说明与演示材料。

Processing Java 本轮交付一个**视觉与运动验证工程**，读取同一参数和匿名状态回放；正式交互原型以浏览器为主。不把两个尚未联通的工程描述成完整装置。

### 5.2 暂缓范围 [方案]
自主捕猎、完整猎物生态、八节脊柱和双骨骼 IK、基因遗传、长者与重生、持续档案、训练新的动作模型、开放对话与云端生成，均不作为本轮验收前提。原型 A 的相关系统作为技术研究材料。

### 5.3 我比较过的三条路线 [方案]

| 路线 | 优点 | 取舍 |
|---|---|---|
| 完全自然手势 + 自主生态（原型 A 方向） | 少界面，观察感强 | 初次参与门槛较高，首轮暂不选 |
| **三个工具 + 需要反馈（原型 B 方向）** | 易理解，便于验证照料因果 | **选为主路线**，用自主休息减少机械感 |
| 直接加入自由对话 | 易表达角色个性 | 增加延迟和内容范围，不能先解决动作理解，暂缓 |

选择第二条路线的代价是观众需要主动切换工具。我的应对是：**让工具表达“准备做什么”，让角色状态决定“现在是否接受”**，而不是把每个按钮都做成必然成功的命令。

## 6 体验流程与界面 [方案]

1. **入口**：作品简介 + 摄像头 / 鼠标两个选项。选择摄像头后才请求视频权限；选择鼠标无需加载手部模型。第一次进入只显示当前工具和一行说明。
2. **体验中**：观察需要 → 选择照料方式 → 根据身体和气泡反馈调整。低精力时休息，饱腹时拒绝进食，低信任时保持更远距离。
3. **收尾**：到达成年或选择结束时，显示本轮有效进食、玩耍和接触统计及关系结语。结语来自固定规则，**不使用生成式文本，不把结局解释为对观众的道德评估**。

界面布局：中央为角色和世界；底部三个工具；左上阶段与需要；右上输入状态和静音；角色附近短气泡。需要条显示相对变化，精确值只在开发调试中显示。

**[待确认]** 首轮公开文案建议英文（“Hold still to pet”“I'm full”“I need a nap”），中文写入独立文案配置；是否提供正式双语切换在启动时确认。

## 7 输入与交互规格 [方案]

### 7.1 输入统一
摄像头和鼠标统一为一个输入对象：`source, x, y, present, speed, confirm, timestamp`。角色逻辑只读取统一对象，避免两套照料规则。

- 位置使用内容区域 0–1 坐标；速度使用“屏幕短边每秒”单位 **S/s**；镜像只在输入端执行一次。
- 手部关键点超过 300 ms 未更新视为丢失，不继续算接触。
- 首次发现手或切换输入时清零速度，避免从无效位置跳入画面被算成惊扰。**相机跳点是系统问题，不能转为信任扣减。**

### 7.2 规则与初始参数

| 项目 | 初始值 | 意义与验证 |
|---|---|---|
| 捏合闭合比例 | 指尖间距 / 掌尺度 < 0.25 | 单次确认，需实际手型验证 |
| 捏合释放比例 | > 0.45 | 开合滞回，防止重复触发 |
| 确认冷却 | 400 ms | 连续捏住只触发一次 |
| 温和移动参考 | < 0.40 S/s | 结合工具、距离与停留判定接触 |
| 快速近身参考 | > 1.10 S/s 且距猫 < 0.18 S | 仅有效轨迹参与警觉判断 |
| 接触确认停留 | 600 ms | 避免仅经过身体就开始抚摸 |

这些是原型起始参数，不是已测得的最佳值。手形在本轮仅用于捏合与关键点有效性；“张手代表抚摸”只作引导，**不宣称系统已理解手形语义**——这是下一阶段动作识别的研究问题。工具栏命中优先于场景命中。

## 8 功能规格 [方案]

| 编号 | 功能 | 规则 | 边界与反刷 |
|---|---|---|---|
| F1-01 | 喂食 | 场内最多 3 份；fullness < 0.85 时寻找最近食物，进食 1.2 s；完成后 fullness +0.25、trust +0.025 | fullness ≥ 0.85 拒食但不扣关系；结算以**吃完**为准而非投放；30 s 未食用淡出 |
| F1-02 | 玩耍 | energy > 0.30 可追逐；接近玩具形成一次扑击：fun +0.12、energy −0.04、trust +0.01 | 扑击最短间隔 1.5 s，不能每帧计数；玩具放远不扣信任 |
| F1-03 | 抚摸 | 身体交互区低速停留 600 ms 后申请接触；非睡眠、非受惊、fullness ≥ 0.20 时接受；每秒 trust +0.02 | 每段最多 6 s 后停顿换位；丢手停止计时；拒绝接触不扣信任 |
| F1-04 | 观察与自主 | 无照料时自主探索、停留、表达饥饿或整理；energy < 0.15 休息至 0.65 | 无人操作不导致死亡，不使用求救式文案催促 |
| F1-05 | 快速靠近 | 低信任 + 有效轨迹近身 + 速度条件 → 短暂退避；首次只给姿态警觉 | 持续 2 s 有效惊扰才少量降信任，单段 ≤ 0.05；丢手、跳点、切换输入不参与扣减 |

## 9 需要模型与行为选择 [方案]

- 初始值：fullness 0.55、fun 0.50、energy 0.80、trust 0.25，均限制在 0–1。
- 衰减：fullness −0.004/s、fun −0.003/s、energy −0.003/s；休息 +0.035/s。全部按实际秒数计算，与帧率无关。
- **优先级状态机**：暂停和结束 → 有效惊扰 → 必要休息 → 完成进食 → 紧急饥饿 → 有效接触 → 寻找食物 → 玩耍 → 低需要提示 → 自主探索。状态切换保留最短动作时间，避免气泡和姿态在同一秒内反复跳变。

> **为什么首轮选状态机而不是原型 A 的效用 AI？** 首轮行为数量有限，优先验证因果与可读性。效用 AI 适合在多个需要同时竞争时扩展；首轮不必为了“更像 AI”而增加一套观众无法理解的决策。机器学习只用于 HandPose 关键点感知，角色决策是可解释规则。（见 [ADR-002](../decisions/README.md)）

## 10 成长与回顾 [方案]

- wellbeing = (fullness + fun + energy) / 3；wellbeing > 0.50 时成长，速度为每秒 1/80 × (1 + 0.25 × trust)。0–1 幼猫丛林，1–2 青年雪地，2–3 成年沙漠；过渡提示约 1.5 s。
- **已知风险**：平均值可能掩盖单项需要不足。我会通过回放和测试检查，若观察到“某项很低仍成长”，下一轮加入单项最低条件（→ PRD V2 F2-13 已采纳）。
- 回顾显示有效进食次数、成功扑击次数、被接受接触时长和一句关系描述；没有成功照料也有中性收尾：“We shared a quiet moment.”
- 演示加速仅在明确的 Demo 模式开放，画面带标记；不能用演示证明正常体验时长。

## 11 AI 和技术实现思路 [方案]

- JavaScript + p5.js 完成运行主链；ml5.js HandPose 提供手部关键点（只在选择手势时加载）；Web Audio 统一合成声音；摄像头失败可立即用鼠标继续。
- Processing Java 做独立的角色运动和视觉研究：PVector 移动、转向插值、尾巴、步态与休息姿态，读取匿名合成状态 JSON 回放。**不运行另一套需要和成长，不与浏览器假装同步。**
- 模块拆分：InputAdapter / CreatureState / BehaviourController / WorldView / SoundAdapter / SessionController / UI；参数和文案独立保存。
- 至少保留一条事件回放：输入、行为切换、有效照料与状态变化，为下一阶段迁移至权威核心提供基线。

## 12 设计表达与无障碍 [方案]

- 为探索、进食、追逐、接触、退避和休息定义运动、姿态、文字与声音映射：接触 = 闭眼/尾巴放松 + 呼噜；退避 = 后退 + 耳部变化 + 短提示；休息 = 蜷缩 + 减慢呼吸。**静音时仍能辨认全部关键状态。**
- 工具有选中反馈和文字标签，不只依赖图标；避免只用红绿表达危险与成功。
- **[待确认]** 鼠标是本轮完整替代输入。键盘方向控制、无捏合操作和完整焦点导航列为下一轮；如客户要求首轮必需，需在范围评审中增加实现和测试时间。
