# Wildling 新版项目委托 Brief（Brief V2）

> **来源：** 项目负责人（客户）· 悉尼游戏交互策展项目 · AI 交互与产品体验升级
> **原件：** [`pdf/brief-v2.pdf`](pdf/brief-v2.pdf)
> **说明：** **全文均为客户提出的要求与边界。** 我的问题判断、方案与取舍见 [`../prd/prd-v2.md`](../prd/prd-v2.md)。

我们希望你将 Wildling 改进为一件可在小型公众展览中独立运行的 AI 互动作品。观众通过手势与虚拟野猫建立短暂关系；系统需要**理解可观察的动作、表达不确定性，并根据本轮相处过程调整回应**。最终作品应让观众理解：建立信任需要观察、回应和尊重对方的节奏。

## 1 委托背景
已有两个方向明确的原型：一个提供自主捕猎、效用决策、程序化身体与生命循环，适合持续观看；另一个提供 Feed、Play、Pet 三种清晰工具和成长结算，适合首次参与者上手。

本轮不是单纯增加场景或给猫加聊天框，而是把两个原型中的有效部分整合为一套可靠的 AI 体验：**观众知道系统是否看见自己，知道自己的动作被怎样理解，也能知道猫为什么接受、犹豫或拒绝。**

## 2 需要解决的核心问题
1. 现有体验把“手移动得慢”直接当作抚摸，把“移动得快”当作威胁或玩耍，无法处理遮挡、跟踪跳点、调整姿势、不同人的动作幅度以及无意经过。
2. 工具选择降低理解成本，也可能让猫变成按按钮就必须服从的对象。
3. 信任是累加或扣减的单一数值。需要以可观察事件形成的**有限记忆**，让猫对成功的互动节奏产生**有边界的适应**，并通过行为表现出来。
4. 展场要求陌生人快速上手、观众轮换、模型加载失败时继续体验，以及运行问题可由工作人员恢复。

## 3 策展主题与叙事立场
- 主题建议为**“学习彼此的距离”**。观众的目标是找到适合当下的相处方式，而非用最快速度把信任条填满。
- 四个可被感知的时刻：第一次被看见；第一次被误解后成功恢复；第一次得到主动靠近；第一次理解退后也是有效互动。
- 不应把观众的动作解释为其真实情绪、人格或心理状态；屏幕中的信任是虚拟角色的模拟状态。
- 保留野性：猫可以暂停接触、拒绝过量食物、结束玩耍并自主休息。高信任降低戒备，不取消身体需要和接触边界。

## 4 用户与现场体验要求
- 覆盖左手或右手、坐姿或站姿、动作幅度较小、不愿使用摄像头和无法完成捏合动作的人。旁观者不默认进入控制权。
- P0 场景：单台电脑、单摄像头、一个主画面、每轮一位操作者。完整体验 3–5 分钟；**前 30 秒内能完成一次有意义的操作**。
- 展览默认英文短文案，中文为交付说明与可切换语言。提示短、具体、无开发术语，例如 “I lost your hand. Try holding it here.”

## 5 体验结构
| 环节 | 要求 |
|---|---|
| 5.1 等待与进入 | 待机画面展示自主活动的猫，提示 “Move closer, or start with a mouse”；开始前说明摄像头用途；等待画面不积累关系记忆 |
| 5.2 建立输入映射 | ≤20 秒轻量引导；检测有效追踪和可达范围，而非强迫统一手势；失败直接提供替代输入 |
| 5.3 探索与相处 | 保留 Feed/Play/Pet，增加“退后或等待”；猫根据需要、压力和历史选择是否接受；合理拒绝要有动作与简短解释；系统误识别不算观众伤害了角色 |
| 5.4 关系变化与结束 | 阶段变化由有效照料、低压力相处和时间共同形成，不能靠持续按住某个动作刷取；结尾 2–3 条有事件依据的回顾；任何时刻可结束；15 秒后自动清场 |

## 6 AI 能力范围
- **6.1 感知（必须）：** 在 HandPose 关键点基础上，增加经过训练并可评估的短时动作分类，至少区分温和靠近、稳定接触、快速近身靠近和普通移动；无手、遮挡、质量不足进入独立的 unknown / lost。不得以单帧速度阈值作为唯一判断。需提交匿名关键点样本、标签定义、按参与者划分的训练与测试记录、混淆矩阵和误触报告。
- **6.2 行为（必须）：** “硬性状态约束 + 效用选择”混合结构；能回答“观察到了什么 / 角色需要什么 / 二者如何影响本次选择”；工作人员可查看输入质量、候选分数和原因，观众只看简短反馈。
- **6.3 有限适应（必须）：** 记录本轮成功接触时长、可接受距离和玩耍节奏，以有界估计调整响应；**至少 3 次有效事件后**才出现可见变化；幅度受限、可重置、结束时清除。可用统计估计，不要求在线训练；必须说明哪些是训练模型、哪些是规则、哪些是统计适应。
- **6.4 扩展：** P1 可恢复完整骨骼、基因与长者循环或匿名关系档案；P2 可尝试受约束的生成式回顾，但不得控制实时动作、修改状态或编造互动。

## 7 功能范围与取舍
| 优先级 | 范围 | 判断标准 |
|---|---|---|
| P0 | 单人完整会话、摄像头与替代输入、三种照料和等待、质量门控、训练动作模型、效用行为、有限适应、解释反馈、结束与清场 | 可在目标设备上完成并验收 |
| P0 | Processing Java 展示端、JavaScript 感知与行为服务、断连恢复、操作说明和测试证据 | 两种技术有真实职责与可运行交付 |
| P1 | 完整程序化骨骼、基因与代际、长期观察模式、主动选择的匿名保存 | 不阻塞核心闭环 |
| P2 | 生成式回顾、多语言自由输入、复杂学习策略、多人控制 | 单独提出变更申请 |
| 不在本轮 | 账号社交、云端视频分析、情绪识别、语音陪聊、商业支付、真实动物照护建议 | 不纳入报价和验收 |

## 8 Processing 与 JavaScript 的实现要求
Processing Java 负责正式展示画面；JavaScript 负责浏览器摄像头输入、关键点与动作识别；本机 Node.js 服务负责唯一的角色状态、效用决策、记忆、会话和日志；浏览器 p5.js 为开发预览与备用展示端。通过本机 WebSocket 传递带版本号的 JSON。角色“大脑”只运行一份。所有展场依赖和模型随离线包提供。

## 9 交互质量与验收目标（模拟项目设计目标，非现有成绩）
| 目标 | 验收要求 |
|---|---|
| 上手 | 10 人中 ≥8 人在 30 秒内无指导完成一次有效动作 |
| 可解释 | 10 人中 ≥8 人能正确说明一次接受或拒绝的具体原因 |
| 公平恢复 | 30 组丢手、遮挡和跳点脚本中，无因无效追踪导致的信任扣减 |
| 关系可感知 | 10 人中 ≥7 人能指出一种由本轮历史影响的行为变化并引用实际事件 |
| 动作识别 | 独立参与者测试集 macro F1 ≥ 0.85，并报告覆盖率与误触 |
| 响应 | 指针反馈 p95 ≤150 ms；意图确认 p95 ≤900 ms |
| 稳定 | 目标设备连续运行 4 小时无崩溃，30 轮清场无状态串入 |
| 可维护 | 工作人员 2 分钟内完成启动、切换备用输入或重启恢复 |

## 10–14 交付、周期、责任与决策（摘要）
- 设计交付：研究计划、两个原型的取舍说明、用户旅程、会话与角色双层状态图、手势词典、模型标签与数据说明、反馈和失败恢复规范、隐私说明、可用性测试记录。
- 工程交付：Processing 工程、JS 输入与行为工程、模型和固定依赖、参数与文案配置、消息协议、可回放事件样本、离线运行包、测试报告、模型评估与已知限制。
- 周期假设：约 34–42 个工作日、8–10 周；付款里程碑参考 20/30/30/20。
- 默认决策：本机离线、Processing 正式展示、英文主界面、每轮一位观众、3–5 分钟、无账号、不保存原始视频、关系记忆仅本轮有效、P0 不调用生成式云服务。
- **交付指令：** 先完成一条可回放、可测量的体验链——观众靠近，系统稳定识别，猫基于状态决定是否接触，观众看见原因，三次有效相处后出现可解释的节奏适应，结束后下一位获得干净的新会话。随后再提高角色运动和环境表现。
