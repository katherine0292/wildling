# Wildling 自查报告：从 V2 到 V3 的重设计依据

> 作者自查。审查对象：`v2/` 构建（1440×900 桌面与 390×844 手机各完整走了一遍，鼠标输入；摄像头手势的结论来自读代码）。
> 用途：记录 V2 的问题、参考研究和 V3 的设计决定，作为后续每一步改动的依据。

---

## 0. 结论

1. **AI 产品层的思考是这个作品最强的部分，体验层是最弱的部分。** PRD、23 条 ADR、追溯矩阵、67 个回放测试（全部通过）、"系统没看见你" 与 "猫拒绝你" 的分离都站得住。但打开链接的前 30 秒看到的是俯视角卡通猫、六个工具按钮和一块像表格的成长面板，文档里的深度没有被体验出来。
2. **"不真实"的根源不是 p5.js，而是五个底层决定**：俯视镜头、工具模式、用文字和面板解释状态、4 分钟长大的成长线、功能铺得太宽。只换贴图不换这五点，仍然会失真。
3. **V3 路线：实时 3D（three.js）猫 + 写实环境 + 低机位镜头 + 无模式的直接互动。** `v2/core/` 是纯逻辑模块，和渲染无关，可以原样保留，这是 V2 架构的回报。
4. **边界：浏览器实时渲染做不到"和真猫无法区分"。** 目标是"可信"：高质量游戏级画面，加上真实的动作、反应延迟和声音。参考研究一致指向同一个结论，真实感主要来自行为和回应，不是多边形数量；画面越接近照片，行为上的一点僵硬越刺眼（恐怖谷）。所以行为、动画分层和音效的投入不低于模型本身。
5. **成长线删除**，改成"关系阶段"。按 G 加速只存在于 `prototypes/a-*` 和 `prototypes/b-*`，V2 里没有这个键；原型里的调试键收到 `?debug=1` 后面。

## 1. 逐项问题排查（从底层逻辑开始）

严重度：**S1** 阻断体验 · **S2** 明显损害 · **S3** 打磨项。

### 1.1 根因层

| # | 根因 | 证据 | 后果 | 级别 |
|---|---|---|---|---|
| R1 | **俯视镜头** | `render.js` 整个世界是正上方视角 | 看不到猫的脸和眼神，无法产生"它在看我"的感觉；真实照片和模型在俯视下也不好看 | S1 |
| R2 | **工具模式**（Feed / Play / Pet / Give space / Siblings / Tricks） | `care.js` `updateDwell`：只有 `tool === 'PET'` 时停留才算数 | 选着 Feed 去摸猫，没有任何反应。这就是"互动很随意、没回应"的直接原因。真实世界里没人先切换"抚摸模式" | S1 |
| R3 | **鼠标下仍然是"速度 = 威胁"** | `intent.js`：摄像头有置信度门槛和 2 次确认，鼠标两者都没有；`fastSpeed` 起点约 0.77 S/s，900px 高的屏幕上约 700 px/s，普通移动鼠标就有 1000–3000 px/s | 实测：鼠标从猫旁边划过一次，立刻出现 "A little more distance, please." 并强制后退 1.2 秒 | S1 |
| R4 | **受惊是二元的，而且往画面外跑** | `care.js` `updateStartle` 一次性 +0.15 stress、强制 RETREAT；`creature.js` 逃跑方向只看手的反方向，边界只是 0.02 的硬夹 | 猫贴到画面边缘、钻到 HUD 面板底下；stress ≥ 0.65 后拒绝一切，玩家不知道怎么挽回 | S1 |
| R5 | **状态靠文字和面板解释** | 气泡里猫用英文说话；左上角成长面板有百分比、3 个章节、4 个环、状态句、下一章解锁 | 一只会说 "I'm full. Let's slow down." 的猫不可能真实；玩家在读 UI，不在看猫 | S1 |
| R6 | **成长线是进度条，不是关系** | `config.js` 成长：漂移 1/150 每秒 + 每次照顾的爆发；实测 15 秒内从 1% 到 22% | 4 分钟从幼猫长成成猫，与"真实"直接冲突；玩家的目标变成刷条。而且写实路线下三个生命阶段意味着 3 倍的模型和动画成本 | S2 |
| R7 | **广而浅** | 6 个工具、3 种玩具、4 种手足请求、3 个把戏、狩猎、礼物、梦、明信片、路人感知 | 每个功能只有一层，彼此不连；"功能之间很突兀"的来源 | S2 |
| R8 | **手势映射是任意的** | 张手 = 交朋友，剪刀手 = 依偎，握拳 = 打架，爪形 = 哈气，而且对象是别的小猫 | 需要背诵，和真实与猫相处的动作没有关系；教程 7 步里 4 步在教这个 | S2 |
| R9 | **定位不清**：展览用的"可解释 AI 装置" 与 "逼真的养猫体验" 在抢同一块屏幕 | 5 分钟上限、30 秒无操作暂停、15 秒自动换人，网页访客也受限 | 作品集访客被当成展览观众赶走 | S2 |

### 1.2 启发式评估（Nielsen 十原则）

| 原则 | 发现 | 级别 |
|---|---|---|
| 系统状态可见 | 状态太多且全是数字和文字；真正重要的"它现在愿不愿意被摸"反而要读句子才知道 | S2 |
| 与真实世界匹配 | 工具栏、数字快捷键、章节、百分比，都是软件概念而不是养猫概念 | S1 |
| 用户控制与自由 | 受惊后没有明确的"道歉"动作；会话会被计时器结束 | S2 |
| 一致性 | 同一个"手靠近"在不同工具下含义不同（喂、逗、摸、无效） | S1 |
| 防错 | 快速移动被惩罚却没有预警（应先有耳朵后压、瞳孔放大等前兆） | S1 |
| 识别而非回忆 | 快捷键 Q/E/T/D/M/1–6、四种手形都靠记忆 | S2 |
| 灵活高效 | 尚可（键盘全流程是亮点） | 无 |
| 审美与极简 | 进入后同屏约 20 个 UI 元素；虚线描边米色卡片与"自然、真实"的基调不符 | S2 |
| 错误恢复 | "系统丢了手" 与 "猫拒绝" 的分离做得很好，建议保留并继续作为核心卖点 | 亮点 |
| 帮助与文档 | 教程是右上角一张文字卡，手形示意图很淡；第一步之前玩家不知道自己的手在哪、猫在哪 | S1 |

### 1.3 其他实测问题

| 问题 | 证据 | 级别 |
|---|---|---|
| **手机端完全不可用** | 390px 宽下教程卡、成长面板、顶部按钮互相遮挡，工具栏被裁切 | S1（招聘方很可能用手机点开链接） |
| ml5 运行时从 unpkg CDN 加载 | `camera.js` `ML5_URL` | S2：离线或网络慢时摄像头模式直接失败，且识别跑在主线程 |
| 兄弟姐妹会走到画面边缘被裁掉一半 | 实测截图 | S3 |
| 声音全部是合成的 | `audio.js` 用噪声加滤波器模拟呼噜和喵叫 | S2 |
| 可用性研究只有计划，没有数据 | `docs/research/` 无 results | S2（对应聘而言这是最容易补、最加分的一项） |

GitHub 之外的依据：

- **Nintendogs / EyePet / Peridot**：评论和开发者访谈反复出现同一个观点，愉悦感来自宠物的**回应**，包括它不理人的时候；完全写实的行为反而不好玩（"只会睡、吃和打架"）；EyePet 团队刻意回避恐怖谷。Niantic 在 Peridot 中用生成式 AI 的方式是**从已有动画库里挑选**合适的反应，而不是生成动作，这和现有"规则 + utility"的思路兼容。来源：[Animals in video games](https://www.wikipedia.org/wiki/Animals_in_video_games)、[Kill Screen](https://www.killscreen.com/today-on-ks-nintendogs-cats-has-its-day/)、[Niantic](https://nianticlabs.com/news/peridot-generative-ai)。
- **猫的慢眨眼研究（2020）**：人对猫慢眨眼后，猫更可能回眨，也更可能靠近伸出的手。这是一个现成的、有科学依据的"AI 感知 + 真实习性"互动点。来源：[Optimist Daily 的报道](https://www.optimistdaily.com/2025/02/want-to-bond-with-your-cat-science-says-you-just-need-to-blink/)（原始论文尚未逐字核对，正式引用前需要查原文）。
- **MediaPipe Gesture Recognizer（Web）**：支持自定义手势模型；官方文档明确说识别会阻塞主线程，建议放进 Web Worker。来源：[Google 文档](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer/web_js)。

### 游戏感、真实感、互动感如何平衡

| 维度 | 做法 |
|---|---|
| 真实感放在 | 猫的外观、动作、习性、声音、光影；没有会说话的气泡 |
| 游戏感放在 | **规则清晰的回应**（每个动作 100ms 内有可见反应）、可发现的隐藏行为、关系阶段的解锁、结尾的日志 |
| 互动感放在 | 猫对"眼前这个人"的注意：眼睛和耳朵跟着玩家的手，记得玩家喜欢摸哪里，认得玩家教它的召唤手势 |
| 取舍原则 | 行为取**真实习性里好玩的那部分**，不做完整模拟；惩罚一律轻、可恢复、有前兆 |

## 3. 重设计方案

### 3.1 一句话定位

**"第一次见面"**：五分钟里，让一只怕生的小猫从躲着看玩家，到主动把头蹭进玩家手里。AI 的部分是它怎么看见玩家、怎么判断玩家、怎么记住玩家，并且随时可以掀开看。

### 3.2 画面与镜头

- **低机位、略俯的三分之二视角**（约猫眼高度往上 20–30°），浅景深，前景有虚化的草叶。猫占画面高度的 25–40%，能看清脸。
- 镜头始终把猫留在安全构图区内，取代现在的硬边界。
- 环境：HDRI 环境光 + 写实地面材质 + 少量 3D 道具 + 远景。**一个场景，三段光线**（清晨、午后金色、黄昏）随关系推进变化，代替三个栖息地，资产量是原来的三分之一，过渡也自然。
- 渲染：three.js，以 ES module 方式放进 `vendor/`，继续保持"无构建步骤"。HDR 管线、ACES、轻微泛光与暗角、接触阴影。按帧率自动降分辨率。

### 3.3 互动模型：去掉工具栏

| 现在 | 改为 |
|---|---|
| 选 Pet 工具，停留等待 | **直接伸手**。慢而低的手会被闻；闻过之后可以摸 |
| 抚摸只有"接触 / 没接触" | **分区抚摸**：脸颊、下巴、头顶最喜欢；背部可以；肚子和尾巴要到很高的信任才行，否则会被轻拍一下。顺毛方向比逆毛好 |
| 选 Feed，点击掉鱼 | 从画面边的**小包**里捏起零食（捏合手势或鼠标拖拽），放在地上或直接摊在手心。摊在手心需要信任 |
| 选 Play，切换三种玩具 | 捏起**逗猫棒**或**球**，物理真实：棒尾巴的羽毛有惯性，球会滚。猫的瞳孔放大、屁股摆动之后才扑 |
| Give space 工具 | 把手收回、移到画面外就是给空间，不需要按钮 |
| Siblings 工具与四种手形 | **删除**。先只做一只主角猫（三种毛色可选）。另外两只留到以后 |
| Tricks 工具 | 改成**"召唤手势"**：教它一个只属于玩家自己的手势（三次示范，沿用现有的 kNN），之后做这个手势它会过来。保留"设备上学习、可查看、离开即忘"的全部卖点 |

新增三个让"AI 在场"被感觉到的互动：

1. **慢眨眼**：摄像头模式下用 MediaPipe 的人脸模型读眨眼。玩家对它慢慢眨眼，它在放松时会回眨，并更愿意靠近。鼠标模式用长按代替。
2. **出声唤它**：麦克风只检测音量和起音（不录音、不做语音识别），玩家发出 "pspsps" 或叫它，它的耳朵先转过来，再决定来不来。
3. **手的远近**：用手在画面中的大小估计"伸进来多深"，突然放大就是扑面而来的手，这比现在的平面速度更接近猫真实害怕的东西。

### 3.4 习性修正：受惊不再是开关

- **分级反应**：耳朵一抖 → 身体一缩 → 后退两步 → 躲到掩体后探头。由"逼近程度 × 距离 × 是否正对 × 信任"连续决定，每一级都有可见前兆。
- **不离开画面**：后退的目的地是场景里的**掩体**（空心木头、灌木、纸箱），躲进去后露出眼睛偷看。这既真实也可爱，还给了玩家明确的"等它出来"的目标。
- **好奇心拉回**：手安静 2–3 秒后它会自己探头；放一颗零食能加快。
- **鼠标与摄像头用各自的阈值**，鼠标的普通移动不再触发。
- **习惯化**：同样的动作重复几次后反应变小（沿用已有的有界适应）。

### 3.5 成长线：删掉，换成关系阶段

| 阶段 | 猫的表现 | 解锁 |
|---|---|---|
| 警惕 | 保持距离、压低身体、从掩体后看玩家 | 闻手、吃放在地上的零食 |
| 好奇 | 主动靠近、尾巴竖起、追逗猫棒 | 摸头和脸颊、手心喂食、回应声音 |
| 亲近 | 蹭手、呼噜、翻肚子、踩奶、在玩家手边睡着 | 摸肚子、召唤手势、带"礼物"给玩家 |

阶段只前进不显示百分比，用光线变化和猫的行为表达。原因：与真实相符；玩家的目标从"刷条"变成"读懂它"；模型只需要一个体型。

### 3.6 界面：从面板到场景

- **常驻 HUD 只留三样**：左上角猫名与关系阶段（一个小标记）、右上角四个图标按钮（输入方式、声音、帮助、结束）、底部一个小包（零食、逗猫棒、球）。
- **状态从猫身上读**：耳朵、尾巴、瞳孔、姿态、呼噜声。
- **"Peek inside" 升级为招牌功能**：按住一个键或做一个手势，画面进入"AI 视角"，显示它看到的手骨架、当前判断（靠近 / 太快 / 没看清）、正在权衡的行为和原因。松开就回到真实画面。平时完全不出现文字。
- **系统层与角色层继续分离**：丢失追踪时变化的是玩家的"手"（变虚、出现蓝色轮廓），猫只是疑惑地看一眼。
- **视觉语言**：去掉虚线米色卡片和圆胖字体，改为半透明磨砂底、细线图标、克制的无衬线或衬线字体，让 UI 退到画面后面。
- **手机**：做成竖屏触摸版本，用手指当手；至少保证不破版。

### 3.7 新手引导：由猫来教

1. **校准即第一幕**："把手伸出来让它闻闻"。检测到手的同时，猫在远处抬头看玩家。不再有单独的校准页。
2. **场景内的"幽灵手"示范**：需要教一个动作时，画面里出现一只半透明的手做一遍（慢慢靠近、停住），玩家跟着做。不用文字卡。
3. **一次只教一件事，做到了才出现下一件**：闻手 → 摸 → 喂 → 逗。其余靠发现。
4. **每步最多一行字**，放在画面下方，6 个词以内。
5. 20 秒没做到就由猫主动降低难度（它自己走近一点），不会卡住。
6. 帮助按钮打开的是一页**动图手势卡**，不是重播教程。

### 4.1 猫的 3D 模型（最关键的一项）

**是否需要多角度参考图**：如果直接采用带骨骼和动画的 3D 模型，就不需要多角度图片。只有在请人建模或用 AI 图生 3D 时才需要参考图（见 4.1.4）。要提醒的是，AI 图生 3D 目前产出的是静态、无骨骼的模型，给四足动物绑骨骼并做 30 段动画才是最贵的部分。**最省事的做法是在 Sketchfab / CGTrader / Fab 上买一个已经绑定并带动画的写实猫模型**（注意许可要允许网页发布）。

#### 4.1.1 模型规格

| 项 | 要求 |
|---|---|
| 格式 | `.glb`（glTF 2.0）。只有 `.fbx` / `.blend` 也可以，可转换 |
| 单位与朝向 | 米，Y 轴向上，真实尺寸（幼猫体长约 0.25–0.30 m，成猫约 0.45 m） |
| 面数 | 3 万–8 万三角面 |
| 骨骼 | 75 根以内。至少：脊柱 5 节、颈 2 节、头、下颌、每只耳朵 2 节、尾巴 6–8 节、四肢含脚趾、左右眼球 |
| 眼睛 | 独立的眼球网格（用于注视和瞳孔缩放） |
| 表情（形态键） | 强烈建议：左眨眼、右眨眼、半闭眼、张嘴。可选：鼻子抽动、胡须前伸 |
| 贴图 | PBR：基础色、法线、粗糙度（可与 AO、金属度合并），2K 或 4K |
| 毛色 | **3 套基础色贴图，共用同一套 UV**：橘色虎斑、灰色斑点、金色玫瑰纹（对应现有的 Ember、Juniper、Saffron）。只做一套也能先开工 |
| 毛发 | 二选一：模型自带毛发面片；或者只给平滑模型，用着色器加绒毛（这时最好再给一张毛长遮罩图和一张毛向图） |
| 数量 | **1 个模型**。按第 3.5 节删掉成长线后不需要幼年、少年、成年三套 |

#### 4.1.2 动画清单

原地动画（不带位移），30 fps，循环的要首尾相接。**加粗的 14 段是最小可用集**，其余可以后补，缺的用程序动画过渡。

| 组 | 动画 | 循环 |
|---|---|---|
| 移动 | **站立待机**、**走**、小跑、**跑**、潜行、后退 | 是 |
| 姿态 | **坐下**（进入）、**坐着待机**、坐起、**趴下**（进入）、**趴着待机**（揣手）、趴起、**蜷睡**、醒来伸懒腰、翻肚子（进入 / 保持 / 退出） | 待机类是 |
| 生活 | **吃**、喝、**舔爪洗脸**、舔身体、挠耳朵、打哈欠、甩头、东张西望 | 吃和舔是 |
| 与人 | **伸脖子闻**、**蹭手**（头和脸颊顶上来）、被摸时享受（眯眼前倾）、踩奶、喵叫（张嘴）、竖尾巴迎接 | 享受和踩奶是 |
| 玩耍 | 伏低摆臀、**扑**、左爪拍、右爪拍、跳起抓、叼着东西走 | 伏低是 |
| 害怕 | **受惊一缩**、**弓背哈气**、压低身体耳朵后贴、从掩体后探头 | 压低是 |
| 把戏 | 转圈、举爪 | 否 |

合计：最小 14 段，完整约 42 段。尾巴摆动、耳朵转动、头部注视、呼吸、眨眼用程序分层实现，不需要外部提供。

#### 4.1.3 采购现成模型时的检查点

- 写明 rigged 和 animated，动画数量至少覆盖最小集；
- 有 glTF/GLB 或 FBX；
- 许可允许在公开网页中使用（很多是"不得再分发源文件"，网页嵌入通常可以，但要读条款，CC-BY 需要署名）；

## 5. 音效

**Web Audio API 本身不用换，要换的是声音的来源。** 现在所有声音都是噪声加滤波器合成的，呼噜和喵叫这类有机声音合成不出真实感。

- **改用真实录音采样**，仍然通过 Web Audio 播放（可以直接用，也可以用 howler.js 管理加载、音频精灵和移动端解锁）。
- **三层结构**：环境底噪（常驻）+ 随机点缀（鸟、风，间隔随机）+ 猫与物件的拟音。
- **与动画同步**：脚步声由动画里的落脚事件触发，不是定时器。
- **连续参数驱动**：呼噜的强度随抚摸的位置和节奏在三档之间交叉淡化；猫在画面左边，声音就偏左，远了就小而闷。
- **变体轮换**：每种声音 3–8 个版本，随机音高 ±5%，避免机械重复。
- **不放背景音乐**，或只在进入"亲近"阶段时加一层很轻的铺底。安静本身是真实感的一部分。
- 保留合成音只用于界面提示音。

| 资产包里的小猫模型 | 用包内 HDRI 逐个渲染模型和 43 段动画 | 结构齐全，但外形是玩具感，多数动作不成立，达不到参考图 |
| 免费的程序化猫库 | three.js 场景，低机位，照片地面与背景板 | 有真实毛发和正确姿态，但整体观感不如 V2 的手绘画面 |
| 照片地面 + V2 的猫 | 把 V2 的手绘地面临时换成地面照片 | 照片细节与卡通猫风格冲突，猫像贴上去的，比原版差 |

调整后的决定：

| # | 问题 | 新决定 | 理由 |
|---|---|---|---|
| 1 | 画面 | **保留 V2 的手绘世界和小猫**，加接触阴影与光影，界面换成深色细线套件 | V2 的猫和背景本来是统一的；三次试验都没有超过它 |
| 2 | 重点 | **流程与交互**，见 [`experience-spec-v3.md`](../design/experience-spec-v3.md) | 自查第 1 节的根因里，R2–R8 都是流程和交互问题，换画面解决不了 |
| 3 | 3D 试验代码 | 不保留 | 只留下地面照片和 UI 套件备用 |

第 3 节里与镜头和 3D 渲染有关的内容（3.2）因此作废；互动模型、习性修正、关系阶段、界面和引导的方向不变。
