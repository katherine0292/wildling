Brief V2 §6.3 要求：**交付中必须准确说明哪些是训练模型、哪些是规则、哪些是统计适应，不能用随机外观变化冒充个性学习。**
本页对仓库中每一部分“智能”如实分类，并标明当前状态。

## 对外可以这样说
- “Wildling 用预训练的手部关键点模型看见你的手，用规则判断追踪是否可靠，并在不确定时说‘我没看清’，而不是惩罚你。”
- “角色用可解释的效用评分在需要之间取舍，安全边界由硬约束保证。”
- “它在本轮里会对你稳定的节奏做小幅、有上限的统计调整，三次有效相处后才会出现，结束就清除。”

## 不能这样说
- ✗ “AI 理解你的情绪 / 善意 / 性格。” —— 模型只输出限定动作类别，不做心理判断。
- ✗ “猫通过机器学习学会了你。” —— 适应是统计估计，不是在线训练。
- ✗ “动作分类模型准确率 xx%。” —— 训练模型尚未完成；规则基线没有经过独立参与者测试，**没有任何准确率数字可以引用**。
- ✗ “本地运行，不需要摄像头权限。” —— 本地推理仍然需要浏览器授权。
- ✗ “每只猫都有独特的学习个性。” —— 原型 A 的外观差异来自随机基因。

## 训练模型的接入点
`v2/core/intent.js` 暴露统一接口 `classify(window) → { label, scores, score, margin, source, modelVersion }`。
规则基线与未来的 TensorFlow.js 模型输出相同结构，因此：
- 质量门控、拒识阈值与 CreatureCore 不需要改动；
- 评估脚本 `tools/evaluate.mjs` 对两者输出同一套指标，可以直接做 PRD V2 §24 的“旧规则 vs 新特征 vs 训练模型”对比；
- 模型缺失或版本不兼容时回退到规则基线，并在诊断面板与日志中标记 `rule_baseline`，**不计入 ML 指标**。
