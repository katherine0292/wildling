# 交付状态看板

PRD V1 §18 约定：**计划、已实现、已验证、客户确认是四种不同状态**，分别维护，不互相替代。
本页按这个口径记录仓库当前的真实状态（更新于 2026-11-09）。

| 状态 | 含义 |
|---|---|
| 📝 计划 | 写入 PRD，尚无代码 |
| 🛠 已实现 | 仓库中有可运行代码 |
| ✅ 已验证 | 有可复现的证据（自动化回放测试 / 浏览器冒烟测试），注明证据类型 |
| 🤝 客户确认 | 项目负责人书面确认（评审记录） |

## 与 PRD 的已知偏差（需评审）

| 项 | PRD | 实现 | 原因 |
|---|---|---|---|
| REST 效用曲线 | 0.10 + 0.90 × (1 − energy) | 0.10 + 0.90 × (1 − energy)² | 线性版本在 energy ≈ 0.6 时就压过探索，猫过于频繁地睡觉；待可用性测试后确认 |
| 闲置行为切换 | 当前 +0.10 惯性、新行为需高 0.15 | 闲置类行为（探索/观察/整理）一轮自然结束后直接重新择优 | 否则整理行为在公式下几乎不可能出现，角色显得机械 |
| 引导到接触的切换 | 同上 | APPROACH → CONTACT 不受切换门槛约束 | 接触是靠近的自然延续；被硬约束拦截的情况不受影响 |
| 惊扰时的退避 | 效用候选 | 确认的近身快速靠近触发短时硬性退避（高信任缩短） | 对应 §13.2“近身压力保护”属于硬约束层 |
| 动作模型 | 训练的 TF.js 时序网络 | 规则基线 | 尚无采集数据；接口已按模型契约设计 |
